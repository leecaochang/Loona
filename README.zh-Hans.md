# Loona

[English](README.md) | 简体中文

[![CI](https://github.com/leecaochang/Loona/actions/workflows/compatibility.yml/badge.svg)](https://github.com/leecaochang/Loona/actions/workflows/compatibility.yml) [![HACS Custom](https://img.shields.io/badge/HACS-Custom-41BDF5.svg)](https://hacs.xyz) [![Home Assistant](https://img.shields.io/badge/Home%20Assistant-2024.6%2B-41BDF5?logo=home-assistant&logoColor=white)](https://www.home-assistant.io)

Loona 帮助你的 Home Assistant Lovelace 仪表盘更轻量地加载和运行。Loona 的工作对你是透明的：你的仪表盘、登录方式和 Home Assistant 地址都保持不变。支持任何设备，只要浏览器是较新的版本。无需代理，也无需额外软件。几秒钟即可安装。**设置好就不用管了。**

## Loona 是如何工作的？

通常情况下，每当你打开一个仪表盘，Home Assistant 都会把每个实体的状态（实体就是 Home Assistant 跟踪的任何对象，例如一盏灯或一个传感器）发送给你的浏览器，然后继续为所有实体发送实时更新。大多数仪表盘只需要或只显示其中很小的一部分。Loona 会找出你所选仪表盘实际用到的实体，并且只发送这些实体。此外，Loona 还可以精简实体、设备、区域、楼层和标签列表，跳过加载你从不使用的卡片文件，延迟绘制屏幕外的图表，并在页面忙碌时暂停动画。

## 效果因环境而异

**数据量更少，并不保证仪表盘用起来更快。** 它确实有帮助，但页面*感觉*有多快，还取决于你的浏览器、设备和网络。请先在你自己的环境中试用并对比，再决定是否依赖它。如果你想看确凿的数据，Loona 自带基准测试工具。如果发现任何异常，你可以通过 **启用** 设置关闭 Loona，Home Assistant 就会恢复正常。

## 系统要求

- Home Assistant (HA) 2024.6.0 或更高版本。
- 较新版本的 Chrome、Edge、Firefox 或 Safari 浏览器，或 Home Assistant Companion 应用。

较旧版本的 Home Assistant 不支持部分功能，建议使用最新的 Home Assistant 版本以获得完整兼容性。Loona 每次加载时都会检测你的 Home Assistant 支持哪些功能，并据此启用相应功能；对于不支持的功能，会悄悄回退到 Home Assistant 的正常行为。

## 安装与首次设置

手动安装：把 `custom_components/loona` 复制到 Home Assistant 配置文件夹中的 `custom_components` 文件夹里，然后重启 Home Assistant。

HACS：把 [https://github.com/leecaochang/Loona](https://github.com/leecaochang/Loona) 添加为自定义存储库，类别选择 **集成**，下载 Loona，然后重启 Home Assistant。

然后进行设置：

1. 打开 **设置 > 设备与服务 > 添加集成**，选择 **Loona**。
2. 选择要让 Loona 筛选的仪表盘。
3. 选择 **所选用户** 或 **所有用户**。Home Assistant 的权限始终有效；Loona 不会授予或移除任何人的访问权限。
4. 可选：安装 **Loona 设置**、**Loona 统计**和 **Loona 基准测试**卡片。Loona 会用这些卡片创建一个 **Loona** 仪表盘，仅管理员可见。不选则跳过此步骤。
5. 请刷新浏览器，以便加载新的仪表盘卡片文件。

## 支持的语言

Loona 的设置与配置界面以及 Loona 仪表盘卡片支持英文和简体中文，会跟随你的 HA 用户资料中的语言。实体和设备名称跟随 Home Assistant 的系统语言。

## 借助 AI 开发

Loona 的开发由一位人类软件工程师主导，并借助了大语言模型（LLM）的协助。如果你对本软件的质量或安全性有任何疑虑，我建议你让自己喜欢的 LLM 去审阅 Loona 代码库，并请它做一次代码审计。

## 使用仪表盘卡片与设置

你可以通过 **Loona 设置** 仪表盘卡片修改设置，也可以通过集成的 **配置** 菜单修改。仪表盘卡片不是必需的。为方便自动化和监控，Loona 还提供了 HA 传感器、开关（用于各项开关类设置）和按钮（用于重新扫描和重置统计）。

如果你在安装时跳过了仪表盘，以后可以自己把卡片添加到任何仪表盘，方法如下：

- `type: custom:loona-statistics-card`
- `type: custom:loona-settings-card`
- `type: custom:loona-benchmark-card`

所有卡片都只有管理员才能安装或查看。安装或升级 Loona 后，请刷新已打开的仪表盘页面，以加载新卡片。

# 进阶

**你已经掌握了开始使用 Loona 所需的全部信息。如果想深入了解 Loona 的功能，请继续阅读。**

## 筛选

只有同时满足以下条件时，Loona 才会筛选某个仪表盘：

 1. 该仪表盘是你选择的仪表盘。
 2. 查看该仪表盘的用户在你选择的 **所选用户** 或 **所有用户** 范围之内。
 3. Loona 已启用，并且至少启用了一项设置。
 4. Loona 能读取该仪表盘上的每张卡片。

其他仪表盘以及 Home Assistant 界面的其余部分不受影响。

编辑仪表盘时，Loona 会向它发送全部实体。停止编辑后，筛选会恢复。

发送到仪表盘的，只有你所选仪表盘实际用到的实体，加上你在 **实体规则** 中添加的内容。

person、update 和 zone 实体无法被排除，因为 Home Assistant 界面需要它们。

**实体规则** 有两个列表：包含和排除：

- 你可以添加单个实体、整个实体类型（例如 `sensor` 或 `light`），或形如 `sensor.kitchen_*` 的匹配规则，它表示名称以 `kitchen_` 开头的所有 sensor。
- “排除”列表的优先级高于“包含”列表。

### 注意事项

Loona 不一定能准确判断自定义卡片或弹窗所需的每个实体。可能只能看到筛选后数据的例子有：

- 快捷栏搜索。
- 弹窗。
- 从已筛选仪表盘打开的服务选择器。

解决办法：在“实体规则”中添加缺失的实体，或在操作期间关闭筛选。

以不寻常的方式请求特定实体的卡片，或监听原始事件的卡片，仍然可能收到全部数据。

### 为什么仪表盘没有被筛选

只有在能确定某个仪表盘需要的每个实体时，Loona 才会筛选该仪表盘。如果无法读取其中某张卡片，Loona 会像未选择该仪表盘一样向它发送全部实体，同时继续筛选你所选的其他仪表盘。此时统计卡片会显示 **部分仪表盘未被筛选**（位于 **警告与检查** 下），并按仪表盘、视图和卡片列出导致问题的每张卡片及其原因。

如果你所选的仪表盘都无法读取，或所选用户已不存在，Loona 会完全停止筛选，并改为显示 **仪表盘扫描不完整**。

| 原因 | 示例 | 解决办法 |
| --- | --- | --- |
| 未选择该仪表盘或用户 | 查看你未选择的仪表盘 | 在“配置”中选择该仪表盘和用户。 |
| 在运行时才决定要读取哪些实体的模板 | 例如使用 `hass.states[variables.room]` 的 button-card 模板 | 在模板中直接写明实体，例如 `states['light.kitchen']`，或把计算移到模板传感器中，然后显示该传感器。在“配置”中添加这些实体无济于事，因为 Loona 仍无法判断该模板还可能读取哪些实体。 |
| Loona 无法读取的 auto-entities 规则 | `template` 筛选、`/regex/` 模式，或只按 `state` 或 `attributes` 筛选的规则 | 在规则中添加 `domain`、`entity_id` 或 `area`。 |
| 仪表盘策略 | 地图仪表盘，或由自定义策略生成的仪表盘 | 不要选择它，或编辑它并保存其卡片。 |
| 尚未保存的自动生成的“概览”仪表盘 | 你编辑之前的默认“概览” | 编辑“概览”并保存其卡片。 |
| 所选仪表盘或用户已不存在 | 选择后又被删除的仪表盘 | 在“配置”中重新更新仪表盘和用户选择。 |

以下情况不会让筛选停止：

- Markdown 卡片、Mushroom 模板卡片、标签、徽章和标题中的模板，以及 card-mod 或 UIX 样式中的模板。这些内容由 Home Assistant 自己填入，因此你的浏览器不需要其中的实体。
- 按 `domain`、`entity_id` 或 `area` 筛选的 auto-entities 规则，即使同时按 `state` 或 `attributes` 筛选。
- 直接写明实体的 button-card 和 Bubble Card 模板，例如 `states['light.kitchen']`。

仅仅是实体 ID 不存在，不会暂停筛选。

## 卡片文件

这些文件通常是通过 HACS 安装的 JavaScript 库。每个仪表盘都会加载 Home Assistant 仪表盘资源中注册的全部卡片文件，即使该仪表盘并不使用它们。Home Assistant 自动生成的仪表盘和地图不使用自定义卡片文件。

选择 **跳过未使用的卡片文件** 后，只会加载你的仪表盘需要的卡片文件。

### 注意事项

Loona 仍会加载它无法确定用途的内容，例如：

- 样式表
- card-mod、UIX 和 kiosk-mode 等辅助工具。
- Home Assistant 被告知要加载的其他文件。
- 尚未见过的新安装文件。
- Loona 无法读取的模板或仪表盘策略（只要在任何仪表盘上发现一个，就会加载全部卡片文件）

Loona 能够理解 button-card、Mushroom、Bubble Card、card-mod 和 UIX 所使用的简单模板。

**额外加载的卡片文件**（位于设置卡片或“配置”菜单的 **卡片文件** 中）可以让你保留 Loona 原本会跳过的特定卡片文件，例如弹窗或其他功能需要、但没有仪表盘用到的文件。这并不是常见的用法。

**优先加载当前选项卡** 会先加载可见的选项卡。其余选项卡会在浏览器空闲时逐个加载，时间点在页面显示完第一个选项卡之后不久。如果该选项卡一直没有报告就绪，剩余的卡片文件会在十秒后加载。

打开弹窗、切换页面或选项卡、编辑，或关闭该选项时，会立即加载全部卡片文件。

**预加载卡片文件** 会让浏览器在被要求之前，就开始下载当前选项卡所需的文件。不会有任何内容提前运行，它的收益取决于你的缓存和网络。

每次修改后，请务必刷新仪表盘。在依赖这些功能之前，请先确认它们在你的环境中工作正常；如果卡片或图标丢失，请关闭这些设置并刷新。

## 图表与动画

**延迟加载图表** 适用于 Home Assistant 内置的使用 `graph: line` 的传感器卡片、Mini Graph Card 和 ApexCharts Card。

可见的图表总是立即加载。屏幕外的图表会等页面稳定片刻后，再逐个开始加载。由于自定义卡片没有统一的“我加载完了”信号，这只是一个有根据的猜测。滚动到被隐藏的图表时，会立即加载。

**加载期间暂停动画** 会在仪表盘启动期间暂停循环的浏览器动画，之后再让它们运行。

**暂停屏幕外动画** 会暂停不可见卡片上的循环动画，并在它们可见时恢复。由 JavaScript 定时器或其他方式驱动的动画，不在这些选项的作用范围内。

## 实验性选项

### 仅实时更新当前选项卡

仪表盘首次加载时，会包含你所选仪表盘用到的全部实体。启用此设置后，只有你正在查看的选项卡会继续获得实时更新。其他选项卡以及其他所选仪表盘会保留各自最后已知的数值。

打开选项卡、打开弹窗或编辑仪表盘时，数值会立即刷新。

如果 Loona 无法确定你正在查看哪个选项卡，它会忽略此设置，让整个仪表盘保持实时更新。从隐藏选项卡读取实体的自定义弹窗可能显示旧数值，因此请在“实体规则”中添加这些实体，或者干脆保持此选项关闭。

### 空闲模式

开启空闲模式后，如果你在空闲等待时间（默认 5 分钟）内没有操作页面，实时更新就会暂停。不建议用于信息展示型的仪表盘，因为仪表盘内容会“冻结”，直到被刷新或再次有操作。

这只影响普通的实时连接，摄像头、独立的时钟、卡片计时器和原始事件监听器仍会继续运行。

#### 空闲等待时间
- 页面在多长时间不操作后进入空闲模式，范围为 1 至 60 分钟（默认 5 分钟）。
#### 空闲刷新间隔
- 空闲期间多久加载一次当前数值的最新快照，范围为 1 至 60 秒（默认 60 秒）。期间的变化不会显示。
- 设为 0 时，数值会一直保持不变，直到你有操作。

## 统计卡片与诊断

**Loona 统计** 仪表盘卡片显示 Loona 筛选了多少内容、是否有功能回退到了正常行为，以及最近的页面加载情况。数字是实时的，每 30 秒刷新一次。各项术语的含义如下：

- **已发送** 是每秒传递给你的仪表盘的实体更新数量。
- **已筛除** 是 Loona 每秒拦下的实体更新数量。
- **已筛除的更新** 是最近一个采样间隔内被拦下的更新所占的百分比。
- **估计精简的实体** 是不在 Loona 已配置的包含范围内的 Home Assistant 实体所占的百分比。它描述的是可能减少的实体数量，而不是实测减少的更新量；即使筛选已关闭，也会显示。
- **总计与实体** 显示重置以来已发送和已筛除的更新、当前包含的实体数量，以及有多少实时连接正在被筛选。可选的图表会以图形展示实体百分比和连接数量。
- **最近的页面加载** 显示每个仪表盘最近一次记录的页面加载中，在可用的实体和卡片文件里被筛除了多少。它不衡量加载时间。
- **浏览器性能** 列出重置以来发送更新最多的 20 个实体，以及浏览器报告的卡顿帧、脚本耗时和可能绕过筛选的事件订阅。这些报告只涵盖浏览器工作量的一部分。
- **警告与检查** 说明检测到的问题和建议的处理方式。**忽略** 会在此浏览器中为你的用户隐藏该类警告，包括今后再次出现的警告。它不会解决问题，也不会改变 Loona 的行为；其他类型的警告仍会显示。

### 计数规则

计数器统计的是属于你所选用户的实时连接上的实体更新。每个连接分别计数一次：如果同一个变化会到达三个连接，就算作三次更新。

实时连接是仪表盘所在的浏览器标签页与 Home Assistant 之间保持的连接。每个打开的标签页通常有一个连接，有时不止一个，因此打开更多标签页会让总数增加。

连接开始时发送的初始实体快照不会被计入。用户无权访问的实体的变化、未被选中的用户的更新，以及 Loona 自身实体的变化，同样不会计入。

被筛选拦下的更新计为已筛除，放行的更新计为已发送，筛选被绕过时也一样。

这些数字衡量的是实体更新，不是数据大小、带宽、CPU 占用或加载速度。

实时计数器会在 Home Assistant 重启时重置，或在你点击 **重置实时统计** 时重置。**自……起** 一行显示当前计数周期的开始时间。

### 图表

**显示统计图表** 默认开启，位于图表下方。如果你自己放置此统计仪表盘卡片，添加 `show_charts: false` 可以让它在启动时关闭图表；之后浏览器保存的选择优先。

图表历史只保存在内存中，重置或重启后会清空。

## 仪表盘基准测试卡片

在设置时选择 **Loona 基准测试**，或在设置卡片的 **Loona 仪表盘卡片** 下选择它，即可把它放到自动生成的 Loona 仪表盘上。通常你不需要在 Loona 仪表盘本身上运行基准测试，而应该测试你自己的仪表盘。在运行真正的基准测试之前，你必须先把这张卡片临时安装到要测试的仪表盘上。你必须是 HA 管理员才能运行基准测试。

1. 按你想测试的方式配置 Loona 的筛选和性能设置。
2. 手动把卡片 `type: custom:loona-benchmark-card` 添加到你想测试的仪表盘选项卡中，最好放在靠近顶部的位置，并保持另一张卡片可见。
3. 点击 **开始**。

基准测试会在那一个选项卡上，用两轮预热和三组交替测试，比较原生 Home Assistant 与你保存的 Loona 设置。请预留约四分钟，并让页面保持在前台，不要滚动、操作或调整窗口大小。页面会自动刷新。

**取消基准测试** 会立即停止测试。

基准测试完成时，Home Assistant 会弹出提示消息通知你。

完成后的 **基准测试结果** 图片会显示可见卡片就绪、初始 JSON 数据、已加载的已注册卡片文件、实时更新速率，以及（在受支持时）浏览器阻塞。它只包含汇总读数和版本信息。

**详细报告** 会打开一份报告，以结果摘要开头，后面是详细的测量说明。

- **复制** 会把 PNG 图片复制到剪贴板。
- **保存** 会把 PNG 图片下载到磁盘。
- **复制文本** 会把报告以 Markdown 文本复制。
- **保存文本** 会把报告下载为 `.md` 文件。

**重新开始** 会清除此选项卡的结果，并把卡片重置，以便再测一次。

**移除** 会把基准测试卡片从通过界面管理的仪表盘中移除。YAML 仪表盘和被手动改动过的卡片需要手动移除。

### 注意事项

**卡片文件大小：** Safari 和适用于 iOS、macOS 的 Home Assistant Companion 应用使用 WebKit，它可能不会报告已缓存脚本的解码后大小，即使文件已成功加载。基准测试结束后，Loona 会尝试通过仅读缓存的方式找回缺失的文件大小。如果某一轮仍然缺少文件大小，**已加载卡片文件** 会改为比较两种模式的文件数量。

**浏览器阻塞：** Loona 会检测浏览器是否支持 [Long Animation Frames](https://developer.mozilla.org/en-US/docs/Web/API/PerformanceLongAnimationFrameTiming#browser_compatibility)。Chrome 和 Edge 123 及以上版本支持它；Firefox、Safari 以及 iOS 和 macOS 版 Companion 应用（WebKit）不支持。不支持的浏览器会跳过阻塞观察器，并在图表、摘要条目和各轮列中省略它。

- 基准测试测量的是使用浏览器缓存的重新加载，不是无缓存加载，也不保证是强制刷新。
- 就绪时间会等待可见卡片和图标渲染完成、可见图片和字体加载完成，以及待完成的原生请求结束。摄像头、图表和自定义内容仍可能在加载。
- 文件大小只涵盖观察到的已注册资源入口文件，不包括每一个被导入的依赖项。
- 无活动、缺失的读数、错误以及重叠的时间范围，都会被明确标出。
- 只有达到设置的空闲阈值，才会出现空闲模式带来的节省。
- 跨域限制也可能导致无法获取文件大小。

## HA 传感器

Home Assistant 中的 Loona 设备包含以下传感器：

| 实体 | 通俗解释 |
| --- | --- |
| 包含的实体、可用的包含实体 | Loona 保留了多少实体，以及其中有多少当前有状态 |
| 估计精简的实体 | 不在该范围内的当前实体所占的比例 |
| 跟踪的连接、已筛选的连接 | Loona 管理的实时连接，以及其中当前被缩小范围的连接数 |
| 每秒发送的实体更新、每秒筛除的实体更新 | 最近一个测量间隔内，平均放行和拦下的变化数 |
| 被筛除的更新占比 | 该间隔内被拦下的已计数变化所占的比例 |
| 已发送的实体更新、已筛除的实体更新 | 自 Home Assistant 启动或上次重置以来的累计总数 |
| 兼容性、仪表盘扫描 | 功能是否可用，以及对你的仪表盘的发现是否完整 |
| 上次成功扫描、扫描耗时 | 最近一次完整扫描何时完成，以及耗时多久 |
| 版本、警告 | 已安装的版本，以及活动警告的数量（不含信息性检查） |

每个所选仪表盘还有自己的 Loona 设备，其中包含 **被引用的实体** 和 **未找到的实体** 两个计数。“未找到”表示该实体既没有当前状态，也没有注册表条目。

## 故障排查

**卡片或选择器中缺少文字或数据：** 先关闭“启用”再对比。检查你的实体规则、所选仪表盘和用户。请记住，从已筛选仪表盘打开的弹窗只能看到该仪表盘的数据。

**卡片或图标缺失：** 关闭“跳过未使用的卡片文件”并刷新。查看“卡片文件”中的可选文件，以及 Home Assistant 日志。

**似乎没有任何筛选：** 检查“启用”“实体筛选”、用户和仪表盘的选择。查看“兼容性”“仪表盘扫描”以及卡片中的任何提示。升级后请刷新浏览器；短暂的启动异常会自动重试。

**扫描不完整或部分仪表盘未被筛选：** 打开统计卡片上的 **警告与检查**。**仪表盘扫描不完整** 或 **部分仪表盘未被筛选** 会列出导致问题的每张卡片；上文的“为什么仪表盘没有被筛选”说明了各自的解决办法。仅仅是实体 ID 不存在，不会导致这种情况。

**兼容性受限：** 检查“兼容性”以及各卡片，看看哪项功能已回退。仍然可用的功能在 2024.6.0 及更高版本上保持可用。另一个 HA 集成也可能正在干扰 Loona，可以暂时停用它来测试。

请在 [Loona issues](https://github.com/leecaochang/Loona/issues) 反馈问题，并附上你的 Home Assistant 版本、受影响的卡片类型，以及集成的诊断信息或基准测试报告。下载的诊断信息和基准测试图片会隐藏用户 ID 和实体 ID、仪表盘路径以及卡片文件地址。详细报告及其 Markdown 副本会列出你已保存的 Loona 设置和浏览器信息，其中可能包含仪表盘和用户名称、实体名称以及卡片文件地址，因此发布前请先检查。

## 卸载

在 **设置 > 设备与服务** 中移除 Loona。这会移除它的卡片文件和已保存的设置，删除 Loona 传感器的长期和短期统计数据，并在你没有编辑过 Loona 仪表盘时将其删除。请移除你自己手动放置的 Loona 卡片。如果你是通过 HACS 安装的，之后请在 HACS 中移除它的文件。

## 开发测试

只需设置一次，需要已安装 uv 和 Node.js 22：

```sh
uv venv --python 3.14 venv
uv pip install --python venv/bin/python -r pyproject.toml --extra test
npm ci
```

浏览器动画测试还需要 Chrome 或 Chromium，如果找不到就会跳过。

像这样运行完整的测试套件、pyflakes 和 mypy：

```sh
venv/bin/python -m pytest tests/ -q
venv/bin/python -m pyflakes custom_components/loona/ tests/
venv/bin/python -m mypy custom_components/loona/
```

完整的开发测试套件固定使用 Core 2026.10.0，并要求 Python 3.14.2 或更高版本。Loona 本身只需要你的 Home Assistant 所要求的 Python 版本。
